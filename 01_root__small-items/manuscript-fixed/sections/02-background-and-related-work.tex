\section{Background and Related Work}\label{sec:related}
\textbf{Counterfactuals and code reasoning.}
Executable Counterfactuals~\cite{vashishtha2026executable} separates \emph{interventional} questions (apply a change,
predict the result) from \emph{counterfactual} ones requiring latent-state abduction; our questions are interventional in Pearl's~\cite{pearl2009causality} sense, keeping the XAI term ``counterfactual explanation''~\cite{wachter2018counterfactual,miller2019explanation} for the contrast \emph{shown to a human reader}. Benchmarks like CRUXEval~\cite{gu2024cruxeval}, CodeMind~\cite{liu2024codemind}, SpecEval~\cite{wang2024speceval}, DexBench~\cite{hasanov2026path}, and CACP~\cite{hooda2024cacp} evaluate model execution tracing and specification compliance. Yang et al.~\cite{yang2025reversion} define \emph{reversion} (predicting original outputs for mutants), while CodeCrash~\cite{lam2025codecrash} exposes model fragility to misleading textual cues.

\textbf{Explaining programs and differential analysis.} Cito et al.~\cite{cito2022counterfactual} explain ML models over code;
WatChat~\cite{chandra2024watchat} debugs users' mental models and Whyline~\cite{ko2008whyline} traces questions. Differential symbolic execution~\cite{person2008dse} formally derives path conditions for divergence. Quantitative symbolic patch impact analysis~\cite{sarker2026impact} uses range-based search to establish sound lower bounds on equivalence over modeled numerical domains. In contrast, \CoDE reports observed agreement on an execution suite. While symbolic conditions could serve as an exact baseline for arithmetic subsets, \CoDE handles arbitrary Python data structures by checking LLM-generated predicates on tests. Automated differential testing tools like Mokav~\cite{etemadi2024mokav}, DIFUZZI~\cite{sun2024difuzzi}, and DiffTestGen~\cite{hu2026difftestgen} search for difference-exposing tests via iterative feedback and coverage loops. Unlike tools that stop at finding a divergence, \CoDE pairs the witness with a test-checked input predicate to articulate the behavioral boundary to maintainers.

\textbf{PR testing, impact analysis, and reliability.} Change impact analysis (Chianti~\cite{ren2004chianti}, Caprese~\cite{fard2023caprese}, Athena~\cite{tufano2023athena}) traces affected call graphs across files. DeepDiff~\cite{sarker2026deepdiff} evaluates regression-freedom for security patches, while ORION~\cite{fu2026orion} extracts PR intent to synthesize structured behavioral oracles for regression gating. In CI workflows, \CoDE complements these gating oracles: it takes a differing test and generates an auditable, human-facing explanation with a test-checked predicate for code review comments. For specifications, nl2postcond~\cite{endres2024nl2postcond} generates formal postconditions. In maintenance, mutation analysis provides realistic fault proxies~\cite{jia2011mutation,just2014mutants,khatib2026mutation,reddy2026articulate}. Because developers are easily overconfident when evaluating unverified assertions~\cite{kaufman2026judges,rong2026behavioral}, certifying both witness and predicate execution provides an essential trust anchor.
